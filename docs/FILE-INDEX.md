# File index

Every file's `FILE GUIDE` note in one place, grouped by folder. This page is generated by `node scripts/file-index.mjs` from the comment at the top of each file, so the two always match.

For the folder map and flow diagrams, see [FOLDER-GUIDE.md](FOLDER-GUIDE.md). For the behind-the-scenes tour, see [HOW-IT-WORKS.md](HOW-IT-WORKS.md).

## app/: the screens

One folder per web address. page.tsx is what you see; actions.ts runs on the server when you press a button.

| File | What it does and what it connects to |
|---|---|
| [app/admin/flags/actions.ts](../app/admin/flags/actions.ts) | Server actions that change Flagsmith: toggleFlag, refreshExperiment, shipWinner. Admin only. They call lib/flagsmith-admin.ts, which holds the secret admin key. |
| [app/admin/flags/console-forms.tsx](../app/admin/flags/console-forms.tsx) | Browser parts of the console: FlagSwitch, RefreshResults, ShipWinner. Calls: ./actions. |
| [app/admin/flags/page.tsx](../app/admin/flags/page.tsx) | Feature console (/admin/flags): the kill switch, the other flag switches, and the EXPERIMENT PANEL (order rate per version, lift, credible interval, chance to be best, Ship to everyone). Uses: lib/flags (current values), lib/flagsmith-admin (results), ./console-forms. |
| [app/admin/leaderboard/page.tsx](../app/admin/leaderboard/page.tsx) | Admin leaderboards (/admin/leaderboard): real names, 'Name shown/hidden' chips, and the seller table. Uses: lib/leaderboard, components/boards, lib/db. |
| [app/admin/metrics/page.tsx](../app/admin/metrics/page.tsx) | Success metrics (/admin/metrics): the experiment (Randomised) plus theme, leaderboard and title-test numbers (labelled Descriptive). Uses: lib/metrics (Postgres numbers), lib/flagsmith-admin (experiment numbers). |
| [app/admin/page.tsx](../app/admin/page.tsx) | Admin home (/admin): this week's orders, the switches at a glance, link to the experiment. Uses: lib/flags, lib/db. |
| [app/cart/actions.ts](../app/cart/actions.ts) | Server actions for buying: addToCart, setQuantity, cartShown (records the EXPOSURE), checkoutStarted / goToReview (checkout_started) and placeOrder (saves the order, sends order_placed). placeOrder re-checks the kill switch and re-prices everything from the database. Uses: lib/flags (Flagsmith events), lib/cart, lib/title-tests, lib/db. |
| [app/cart/checkout-controls.tsx](../app/cart/checkout-controls.tsx) | Browser parts of checkout: ExposureBeacon (tells the server 'the cart is on screen'), PlaceOrderButton, and ExpressCheckout (the one-step confirm sheet). Used by: app/cart/page.tsx and app/checkout/page.tsx. |
| [app/cart/page.tsx](../app/cart/page.tsx) | Cart page (/cart). THE EXPERIMENT LIVES HERE: asks Flagsmith which checkout version you get and shows [Checkout] (control, two steps) or [Order now] (express, one step). | [app/checkout/page.tsx](../app/checkout/page.tsx) | Review page (/checkout): step two of the CONTROL version only. Express users are sent back to /cart. Uses: lib/flags, lib/cart, ../cart/checkout-controls (PlaceOrderButton). |

| [app/layout.tsx](../app/layout.tsx) | The frame around every page: loads the fonts, the global styles and the header. Also runs a tiny script before the page paints so your White/Dark choice shows instantly. Uses: components/site-header.tsx. Used by: every page in app/. |
| [app/leaderboard/page.tsx](../app/leaderboard/page.tsx) | Public leaderboard (/leaderboard): top kitchens and customers, this week or this month. Hidden when the leaderboard_enabled flag is off. Hidden-name sellers show as 'Anonymous seller #N'. Uses: lib/leaderboard, components/boards, components/page-view (logs leaderboard_view). |
| [app/loading.tsx](../app/loading.tsx) | The grey placeholder blocks shown for a moment while a page is loading. Used by: Next.js automatically, for every page. |
| [app/login/actions.ts](../app/login/actions.ts) | Server actions for login: signInAs saves your user id in a cookie; signOut clears it. Used by: app/login/page.tsx and the 'Switch account' button in components/site-header.tsx. |

## lib/: the brains

No screens. Talks to Flagsmith and the database, and holds the business rules.

| File | What it does and what it connects to |
|---|---|
| [lib/cart.ts](../lib/cart.ts) | Builds a cart from the database and works out prices (dish discount, then store discount). Prices never come from the browser. Used by: cart page, checkout page, placeOrder. |
| [lib/db/index.ts](../lib/db/index.ts) | Opens the Postgres connection (Drizzle ORM). Everything that reads or writes data imports `db` from here. Connection string comes from DATABASE_URL in .env.local. |
| [lib/db/schema.ts](../lib/db/schema.ts) | The database tables: users, sellers, themes, items, store_discounts, title_tests, title_events, user_prefs, orders, order_items, cart_items, events. `npm run db:push` creates them. |
| [lib/flags-types.ts](../lib/flags-types.ts) | Shapes and defaults for the theme_options remote config, safe to use in the browser. Used by: lib/flags.ts, lib/theme.ts, app/seller/themes/editor.tsx. |
| [lib/flags.ts](../lib/flags.ts) | THE FLAGSMITH CONNECTION (Node SDK, server only). Reads flags for a user, works out the checkout version, records exposures, sends events (add_to_cart, checkout_started, order_placed), flushes them. If Flagsmith is down it returns safe defaults. Used by: almost every page and action. |
| [lib/flagsmith-admin.ts](../lib/flagsmith-admin.ts) | Flagsmith ADMIN API (server only, uses the secret admin key): flip a flag, read experiment results, refresh them, and ship the winner (complete the experiment). Used by: app/admin/flags and app/admin/metrics. |
| [lib/leaderboard.ts](../lib/leaderboard.ts) | Leaderboard SQL: ranks sellers and customers for this week or month (India time), and shows hidden sellers as 'Anonymous seller #N'. Used by: both leaderboard pages. |
| [lib/metrics.ts](../lib/metrics.ts) | SQL for the admin metrics page: theme adoption, opt-outs, theme impact, board views, name visibility, growth, title tests, top-3 share. Used by: app/admin/metrics. |
| [lib/queries.ts](../lib/queries.ts) | Small shared queries and helpers: kitchen cards, last order, India week/month start, rupees(). Used by: many pages. |
| [lib/resolve-theme.ts](../lib/resolve-theme.ts) | Decides which look a store shows, first match wins: flag off, customer opted out, seller's look, default. Used by: the store page and recordStoreView. |
| [lib/session.ts](../lib/session.ts) | Who is signed in: reads the login cookie, and requireUser / requireSeller guards. Every page and server action calls these first. Uses: lib/db. |
| [lib/store-data.ts](../lib/store-data.ts) | Loads one store: seller row, menu, active discount, own looks and Platter looks. Used by: store page, theme studio, menu pages. |
| [lib/store-fonts.ts](../lib/store-fonts.ts) | Loads the 4 fonts sellers may pick (Inter, Poppins, Merriweather, Space Grotesk). Used by: components/storefront.tsx. |
| [lib/theme.ts](../lib/theme.ts) | Look helpers (server and browser): contrast ratio, colour variables for a store, text cleaning, and checking a look against theme_options. Used by: studio, storefront, seller actions. |
| [lib/themes-default.ts](../lib/themes-default.ts) | The 3 Platter looks (Classic, Night, Fresh). Used by: the seed script and the theme resolver. |
| [lib/title-tests.ts](../lib/title-tests.ts) | Seller title tests: which title a customer sees (stable hash of user + test), logging view / add_to_cart / order, and per-title results. Used by: store, cart, seller test page. |

## scripts/: run by hand

npm commands for demo data, Flagsmith setup and simulated traffic.

| File | What it does and what it connects to |
|---|---|
| [scripts/file-index.mjs](../scripts/file-index.mjs) | Builds docs/FILE-INDEX.md from the FILE GUIDE comment at the top of every file. Run: node scripts/file-index.mjs (re-run after changing a header). |
| [scripts/flagsmith-setup.mjs](../scripts/flagsmith-setup.mjs) | Creates everything in Flagsmith: the 6 flags, the order_placed metric and the experiment. Run: npm run flagsmith:setup   (add --start to start the experiment). |
| [scripts/seed.mts](../scripts/seed.mts) | Fills the database with demo data (wipes it first): 1 admin, 3 sellers, 5 customers, 20 dishes, 3 weeks of orders. Run: npm run db:seed. |
| [scripts/simulate.ts](../scripts/simulate.ts) | SIMULATED TRAFFIC for the experiment: fake customers get a version from Flagsmith and order at the rates set at the top. Run: npm run simulate (or -- --dry-run to send nothing). |

## Project root: settings

Config files at the top of the project.

| File | What it does and what it connects to |
|---|---|
| [docker-compose.yml](../docker-compose.yml) | Starts the Postgres database in Docker on port 5433. Run: npm run db:up. |
| [drizzle.config.ts](../drizzle.config.ts) | Tells drizzle-kit where the tables are defined (lib/db/schema.ts) and which database to update. |
| [eslint.config.mjs](../eslint.config.mjs) | Code-style checks (npm run lint). |
| [next.config.ts](../next.config.ts) | Next.js settings: Cache Components on, and a 2.2 MB upload limit for banner images. |
